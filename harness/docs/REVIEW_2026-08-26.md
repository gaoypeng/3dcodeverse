# Harness backend — reorganisation plan

Scope: `~/3dcodeverse/harness` (`codeverse/`, `bench/`, `runtime_js/`, `tests/`, `docs/`).
Inputs: 19 verified findings (each survived an adversarial re-check), 1 refuted, 28 unverified,
four reader do-not-touch lists, the god-file inventory. Every item below cites the verdict's
evidence, not the original claim; where the verdict narrowed a proposal, the narrowed version is
what is written here. All line numbers are as of 2026-08-26.

## 1. Verdict

The codebase is in good shape for its age: the seven laws are visibly enforced (typed contracts,
`TRACK_INFO` as single source, the `_<family>.py` shared-helper pattern, a test that pins the
package map to `docs/ARCHITECTURE.md`), and almost every oddity a reviewer flags turns out to
carry a dated measurement or an ADR — of ~1,000 removable lines, fewer than 300 are in
production paths; the rest is stranded scaffolding. The real mess is **wave residue**: things
built in parallel that were never reconciled once the siblings landed — a second HTML gallery
(`flywheel/gallery.py`) that the CLI already abandoned, `call_adaptive` silently dropping
kwargs to signatures that now exist, a compat shim with its own delete-me TODO, a headless
Blender renderer with zero callers, a `material_pass` no command runs, and the same tolerant
JSON/JSONL read loop written eight times because `proc.py` never grew the helper. What is NOT
mess despite the look: `storm.py` shipped OFF, `cost/caching.py`'s measurement-only helpers,
`budget.charge/add` both forwarding to `spend`, the StopPolicy ordering, `plan_features.py`'s
dead switch, the wrapper helper twins under `languages/*/wrappers` (Blender's python cannot
import `codeverse`), and `tracks/common.Services` forwarders — every one is a documented,
measured decision (see §3), and the one "duplication" finding that targeted a documented corpus
definition (`complexity_report.iter_runs`) was refuted for exactly that reason.

## 2. The plan (ordered: low-risk deletions → shared helpers → behaviour-touching dedupes → package moves)

Convention: **T** = the exact command that must be green before and after. Unless stated, run
with `-p no:cacheprovider -m "not live"`. After every deletion item also run `ruff check codeverse bench`
(F401 orphans are called out per item). Items marked **[land together]** share a file or a helper.

## 4. Structural observations (not cleanups)

1. **`codeverse/proc.py` is the de-facto stdlib utility layer but never grew with the tree.** Eight tolerant
   JSON reads, five tolerant JSONL reads and two JSONL writers exist because the documented "shared primitives"
   module offers only `write_json_atomic`/`run_subprocess`/`tail`. B2+B3 fix the instances; the recommendation is a
   rule in CLAUDE.md or ARCHITECTURE:85 — "any stdlib-only file/JSON/JSONL helper lives in `proc.py`; grep it
   before writing a try/except read" — and to keep `proc.py` under ~250 lines so it stays a leaf. Cost: one doc line.

2. **`codeverse/flywheel/` has quietly become two packages.** Records/telemetry/export/dedupe (the data flywheel)
   and gallery/captions/quality (presentation) drifted apart when `codeverse/gallery/` was born in 8f3149d; D2
   removes the stale half, but `flywheel/captions.py` and `quality.py` are consumed by `gallery/index.py`
   (`quality_tier`, captions) as much as by export. Recommendation: after D2, decide whether `gallery` depends on
   `flywheel` (current, fine) or the shared bits move to `flywheel/record.py`'s neighbours — write the arrow into
   ARCHITECTURE §11 either way. Cost: a doc paragraph now; a small move later if wanted.

3. **The `judges/` ↔ `cli/_judge.py` boundary is right but unwritten.** `judges/` imports nothing from
   tracks/flywheel/workspace/orchestrator while all of those import `judges/` — that is a real, valuable layering,
   and it is why C3 stops short of moving `build_judge_input`. It is enforced by nobody: `test_docs.py` checks the
   package map, not import direction. Recommendation: a ~20-line import-direction test (parse `import` statements
   under `codeverse/judges`, `codeverse/contracts`, `codeverse/proc.py`, assert no edge into tracks/flywheel/cli/
   orchestrator). Cost: one test file; catches the next wave's inversion before review.

4. **Wave-marker comments outlived the waves.** Nine "package C1/C2/E/F" comments, "written in parallel" docstrings
   (`call_adaptive`), "for one wave" shims (`texture_pass` judge union), "TODO(follow-up wave)" (`gl_build`) and
   `reference/prompts.py`'s "must not couple to files another wave edits" are the trace of the parallel-authoring
   process, not of the design. Recommendation: after Waves A-B, one sweep that either deletes each marker or
   converts it into an ADR line in DECISIONS.md; then adopt "no wave names in code — put the reason in DECISIONS".
   `reference/spec_text.py` vs `tracks/prompting.constraints_text` is the one remaining pair whose only justification

   reference-cache invalidation).

   The tracks package carries seven of them, and three (`lifecycle.py` 714, `generation.py` 675, `rounds.py` 598) have
