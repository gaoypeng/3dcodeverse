3dcodeverse · backend harness

LLMs write raw 3D code. The harness builds it, measures it, judges it, and keeps the receipts.

3dcodeverse is a data flywheel for raw-language 3D code generation. A model is handed a prompt and a language contract — pure bpy, pure CadQuery, pure three.js, hand-written URDF, plain GLSL — never an SDK or a helper library. The harness owns everything around the code: planning, the workspace, the build wrappers, deterministic geometry gates, the render rigs, the VLM judge, the budget, and one record.json per run. What comes out is not just a model: it is code + the evidence that the code is right, which is exactly the training signal a raw-3D-codegen model needs.

The seven authoring frames

Frames and units live in exactly one file, codeverse/conventions.py; every prompt, gate hint and wrapper imports them rather than restating them.

LanguageAuthoring frameEntry file
blenderZ-up, −Y frontsrc/model.py + src/parts/*.py
cadqueryZ-up, −Y frontsrc/model.py (module-level result)
urdf_blenderZ-up, −Y frontsrc/model.py + src/robot.urdf
threejsY-up, +Z frontsrc/object.js + src/parts/*.js
scene_threejsY-up, +Z frontsrc/scene.js
glsl_shaderscreen spacesrc/shader.frag
opengl_pythonscreen spacesrc/program.py

Everything is exported to the GLB frame (Y-up, +Z front) and metres. Gate fix hints are translated back into the author's frame, so a Blender agent is told "translate by (0, 0, +0.005) m — blender frame: Z-up, −Y front", never a GLB vector.

Nine laws that shape everything below

  1. Code is truth; GLBs and renders are derived and regenerated from the best commit.
  2. Raw language only — the harness owns wrappers, exporters, camera rigs, URDF math.
  3. Code answers when code can answer. Deterministic gates first; the VLM only perceives.
  4. The score is computed in code from rubric weights, floors, caps and defect votes — the model never returns an "overall".
  5. Concrete beats abstract: contracts ship as skeleton code, exact numbers and runnable cookbook snippets.
  6. Cheap first: lint → build → gates → montaged views → VLM.
  7. Cost is a budget, not a log — hard per-run ceilings, one Usage per call.
  8. Export as authored — no wrapper re-centres or grounds anything; the gate complains, the agent fixes the source.
  9. Reproducible: prompt/rubric hashes, tool versions and a git commit per round.

Full text with the reasoning: ARCHITECTURE.md §1, DECISIONS.md.

The layers, and what flows between them

Each band is one Python package (generation is the models/ + agents/ pair). Nothing skips a layer, and every arrow carries a typed pydantic object from codeverse/contracts/ — there are no stringly-typed dicts crossing a package boundary and no regex-on-id control flow. 03

What a run actually does

3dcv make "a mid-century wooden dining chair" --track static_object --language blender → spec → plan → skeleton → workspace → baseline round → refine rounds → finalise → record. Stages are input-hash cached, budgets are checked between steps, and every round is a git commit of src/.

What stops a run

stop_reasonMeaning
passthe last round's Judgment.passed is true: overall ≥ rubric threshold, no criterion under its floor, every must acceptance item satisfied.
plateauno round improved by min_delta (0.02) over the plateau_window (2). Also raised when a refine round changed no file at all (no_change) or produced no tasks.
budgetBudgetGuard tripped on max_usd or max_minutes. Checked between steps, and a fully judged round is promoted to best before the check — a paid-for verdict is never thrown away.
max_rounds--rounds N refine rounds are done (default policy max_rounds=4).
judge_unavailablethe build was clean but the judge never returned a usable verdict (outage, or a degraded verdict). The round is re-judged once on the same commit; if that also fails the run stops here rather than blaming the code for a judge glitch.
failedan exception escaped the round loop (baseline generation failed outright). record.json is still written with status=failed; 3dcv resume restarts at the last completed stage.

Degraded judge verdicts are recorded and paid for but never scored — a 0.0 from a broken verdict must not poison plateau detection or best-round selection.

Where git commits happen

  • spec — the workspace is created by the CLI.
  • skeleton — the buildable placeholder the language runtime writes from the plan.
  • env / zones / assets / assemble — scene stages.
  • pre:<label> then agent:<label> — every agent session brackets itself with two commits, which is how files_changed is attributed between concurrent sessions in one workspace.
  • rNN <kind>: generated — right after generation, before the build.
  • rNN <kind> — the round's commit, recorded as RoundRecord.commit.
  • r00 baseline: candidate c<k> selected (best of N) — best-of-N winner copied back.
  • restore best round rNN — finalise checks out the best commit and rebuilds so the shipped artifacts match the shipped code.

That history is half the flywheel: flywheel pairs mines (round i, round j) preference pairs by judge delta and replays repair pairs against the git snapshots to verify they really fix the build.

Cheap first is a hard rule, not a preference. A round costs a lint (milliseconds), a build (0.1–0.6 s for Blender, 2–5 s for a 12-frame GL render), deterministic gates (fast, local), an 8-view GPU render (~1.5 s) — and only then a VLM verdict at $0.02–0.03 on flash or ~$0.07–0.2 on pro. The expensive step is last, sees montages rather than loose views, and is skipped entirely when the build failed.
04

The four tracks

A track is a BaseTrack subclass plus a RoundPipeline. The base class owns the round loop; the track supplies the plan model, the prompts, the gates, the render rig and the rubric. Every screenshot below is a real artifact from this repo, embedded as a data: URI — nothing here is a mock-up.

track · static_object

Static object — one rigid thing, measured to the millimetre

blender (bpy, multi-file) · cadquery · threejs (ESM)  →  artifacts/object.glb + .stl / .step

Authoring contract

  • One file per plan part, one object per part, PascalCase names. src/parts/<snake>.py exports build_<snake>(); src/parts/<snake>.js exports build<Pascal>(THREE). Instances are looped inside that one file and stay top-level — a parent Empty would merge them into one measured part.
  • Plan numbers used literally, in metres, at world pose. Z-up / −Y front for Python, Y-up / +Z front for three.js; lowest point on the ground plane; the footprint centred on the up axis. No re-centring, no rescaling — the harness exports as authored.
  • Touch or overlap, never float. Seams overlap by ≥ 2 mm (CONTACT_GAP_M); a floating piece is fixed by embedding it in its neighbour, never by adding a connector rod. Hollow things are actually hollow.
Gates
lint:<lang> (forbidden imports, ops, structure) → build (errors mapped to src/parts/<file>.py:line) → connectivity (contact graph, exact gap vector to close, interpenetration, stray islands) → contract (every plan part present, per-part bbox delta, overall size vs BBOX_TOLERANCE_M = 1 cm, ground contact). With a reference image: reference_silhouette (front-view IoU; < 0.6 adds a refine task).
Rubric static_object_v1 — pass ≥ 0.72
intent fidelity 0.22 · structural plausibility 0.18 · geometry detail 0.16 · proportions & scale 0.12 · assembly fit 0.12 · materials 0.10 · craftsmanship 0.10. Floors on intent (0.30), structure (0.25) and craftsmanship (0.30); deterministic caps build_error → 0.0, floating_part → 0.6, penetration_error → 0.7, contract_violation → 0.75, missing_must_acceptance → 0.6; 10 binary defects (wrong_object alone caps at 0.25).
track · articulated_object

Articulated object — bpy link meshes plus a hand-written URDF

urdf_blender  →  src/robot.urdf + artifacts/meshes/<link>.glb (raw link frames) + object.glb (node hierarchy carrying joint extras)

Authoring contract

  • One mesh object per link, built in world coordinates at the rest pose. q = 0 is what you build: doors closed, drawers in, lids down. The harness never opens anything for the showcase.
  • Every joint rpy="0 0 0"; the link frame is its pivot. <joint><origin xyz> = pivot_child − frame_parent, and both <visual> and <collision> origins are −pivot because the mesh file holds world coordinates. This is the line everyone gets wrong, so an FK-consistency check verifies it numerically to 1 mm and prints the corrected origin when it fails.
  • Signs come from behaviour, not from swapping limits. Positive q must open the door, pull the drawer out, lift the lid; if it does not, negate the axis. Limits are plan.lower − rest .. plan.upper − rest with lower ≤ 0 ≤ upper. Single-root tree, ≤ 60 links, link name world reserved.
Gates
everything the static track runs, plus joint_sweep — every joint stepped across its range, deterministic penetration testing (oriented islands + a fixed-direction parity ray test; python-fcl is a core dependency and the trimesh fallback is deterministic too) — plus motion_direction, which compares the URDF axis against the plan's motion prose ("pulls out to the front") using real FK.
Rubric articulated_v1 — pass ≥ 0.70
articulation plausibility 0.18 · intent 0.16 · structure 0.14 · joint placement & range 0.12 · geometry detail 0.12 · proportions 0.10 · assembly fit 0.10 · craftsmanship 0.08. Extra caps: urdf_error → 0.3, joint_collision → 0.6, unattached_link → 0.6, and missing_pose_sheet → 0.5 — the verdict is capped if the judge was not shown the pose views.
track · scene

Scene — a multi-file three.js world, assembled in stages

scene_threejs  →  src/scene.js, src/env.js, src/zones/*.js, src/assets/*.js, src/shaders/*.js + public/assets/*.glb

Authoring contract

  • createScene({THREE, renderer, loaders}) → {scene, cameras, update(t, dt)}. Cameras are plain objects ({name, position, lookAt, fov}) — the harness builds the real PerspectiveCameras. The first camera is the establishing shot and must show ≥ 70 % of the declared bounds; human views sit at ≈ 1.6 m.
  • The scene is split so it can be built in parallel. env.js owns BOUNDS, heightAt(x, z), lights and fog; each zone is one file returning one named Group; assets are procedural or Blender-built GLBs under public/assets/. The harness assembles scene.js deterministically — the model never writes the glue.
  • Deterministic and cheap. No Math.random() (seeded hash), no Date.now() (use t), no DOM, no fetch, no renderer creation. ≤ 2 M triangles, ≤ 200 draw calls, update() under 4 ms with no allocations.
Stages (each input-hash cached, resumable)
assets — every Blender-built GLB gets its own sub-workspace, an asset_v1 judge and one fix pass, all in parallel → env → zones (parallel) → assemble (deterministic).
Gates
probe_scene + check_shaders (headless Chrome: census, triangles, draw calls, fps, console and shader errors with line numbers), then post-render render_console and scene_frames — dark / blown / flat frames, camera inside geometry or underground, content too small in frame. Authored cameras raise ERRORs; the overview rig only WARNs.
Rubric scene_v1 — pass ≥ 0.70
brief fidelity 0.18 · composition & camera 0.14 · lighting & atmosphere 0.14 · asset quality 0.14 · spatial coherence 0.12 · materials & shaders 0.12 · animation 0.08 · technical cleanliness 0.08. The frame gate feeds caps directly: dark_frame → 0.55, blown_frame → 0.6, flat_frame → 0.65, camera_in_geometry → 0.5, content_small → 0.6.
track · graphics

Graphics — animated shaders and raw OpenGL, judged as a sequence

glsl_shader (Shadertoy-style fragment shader) · opengl_python (raw moderngl + GLSL, multi-pass)  →  source + frames/ + frames_sheet.png + preview.gif + metrics.json

Authoring contract

  • The model writes only the body. No #version, no uniform declarations, no out vec4 — the harness header supplies u_time · u_resolution · u_mouse · u_frame · u_prev · u_noise · u_buffer_a plus Shadertoy aliases (iTime, iResolution, iChannel*), and a line map turns compile errors back into src/shader.frag:line.
  • Optional feedback pass. src/buffer_a.frag plus src/common.glsl; feedback shaders are simulated forward at 30 fps so u_prev is a real history, not a black texture.
  • OpenGL programs are two functions — setup(ctx, w, h) → state and render(ctx, state, t, frame, fbo). moderngl only: no window library, no wall clock, no file writes. Each render runs in a fresh subprocess (GL contexts are not thread-safe), d3d12 GPU first, llvmpipe fallback.
Gates
gl_frames, computed from the rendered sequence itself: nan · black · blown · static · flicker · low_detail · duplicate · no_frames. There is no GLB and no measurement on this track — the frames are the artifact.
Rubric shader_v1 — pass ≥ 0.70
brief fidelity 0.24 · visual richness 0.18 · motion quality 0.14 · composition 0.12 · colour & light 0.12 · technical cleanliness 0.12 · originality 0.08. Hard caps straight off the frame gate: nan_pixels → 0.0, black_or_blown → 0.5, static_frames → 0.5, flicker → 0.7.

Optional: the texture pass (a derived asset pack — object.glb is never touched)

One VLM material plan maps parts to shared texture ids with a material family, a projection (planar / box / cylinder) and a real-world tile_size_m. Those become text-to-image tiles (gemini-3.1-flash-image, ≈ $0.07 each, cached by prompt), made tileable with a mirror cross-fade and gated at seam_score ≤ 0.08. Then a world-metre UV unwrap gives every part identical texel density, and the result is written to artifacts/object_textured.glb.

It ships only if a before/after judge run says Δoverall ≥ −0.01 and the materials criterion improved. On the park bench the gate said no (materials −0.250) and the pack was kept but not shipped — which is the behaviour you want from a gate.

Scenes get scene_texture_pack instead: 6–12 named tiles plus public/textures/manifest.json, injected into zone prompts as an "Available textures" block.

CLI: 3dcv texture pass <slug> · 3dcv texture scene-pack <slug> · 3dcv texture show <slug>, or --texture on make. Object-track agents can also call the texture_pass / texture_preview tools mid-session.

Backends — who writes the code

Two protocols and one escape hatch. ChatModel is a request/response API model (models/base.py); CodingAgent is an agentic session against a workspace (agents/base.py); single-shot is neither — it is one structured-output call returning a multi-file envelope, handled inside tracks/generation.py. Ids are always <kind>:<model>, and Spec.backends assigns one to each of the four roles: planner · generator · judge · captioner.

The same tools, three ways

A spatial tool is registered exactly once. The registry then exposes it as (a) a direct Python call from a track, (b) a stdio MCP server named 3dcv for gemini-cli / claude-code / codex, (c) a native function schema for api-agent, and (d) a prompt card in the workspace brief. Adding a tool lights up all four at once.

materialize_workspace writes the same brief body to AGENTS.md, GEMINI.md and CLAUDE.md, plus the per-agent MCP wiring and the .geminiignore / .aiexclude that keep renders, judge output and transcripts out of the agent's context while leaving build and measurement JSON readable.

Cost is a budget, not a log

Every call returns a Usage with a real cost_usd from models/pricing.py (a prefix fallback matches only pure version suffixes — a -mini or -codex sibling never silently inherits its parent's price; it is priced as unknown with a warning). BudgetGuard holds the run to max_usd / max_minutes and is checked between steps.

Known gap: a refine round that finishes its judge and then trips the budget is promoted to best before the loop stops — but give scenes --max-minutes 60 --max-usd 4 anyway.

The measured numbers

All figures below are read off bench/out/<battery>/report.md and runs/<slug>/record.json as of 2026-08-23. Judge for every battery: gemini:gemini-3.1-pro-preview, rubric fixed per track, acceptance items from the battery's must_have list. Generator gemini-3.7-flash throughout.

How a score is produced

The judge sees montages, not loose views

  • ≤ 3 labelled 2×2 montages — shaded, geometry-only (clay or normals, which exposes holes and intersections that materials hide) and, for articulated runs, poses — plus ≤ 2 detail crops, all at ≤ 1024 px, shuffled per sample.
  • The wire schema is observe-then-score: summary → strengths → issues → defect checklist → acceptance results, and only then the criteria. Putting criteria last measurably restored flash's dynamic range.
  • The model never returns an overall. Defect votes are majority (ties → present) and overall = caps(weighted_mean − Σ penalties). Floors, deterministic caps from gate findings (matched on GateFinding.data["kind"]), console errors, missing must-acceptance and missing_views rules apply on top. passed = overall ≥ threshold ∧ no floor ∧ all must-acceptance.
  • Generator and judge are separated: the judge sees the spec, the renders, the measurements and the acceptance list — never the generator's reasoning.

How to extend it

Five plugin paths. Each one is a handful of files plus one registry entry — if you find yourself editing the orchestrator to add a language, you are on the wrong path.

A new language

  1. Add the enum member to contracts/common.py::Language and its rows in TRACK_LANGUAGES, ENTRY_FILE, LANGUAGE_LABEL; add its frame to conventions.LANGUAGE_FRAME.
  2. Write languages/<lang>/{runtime.py, lint.py, skeleton.py, wrappers/} implementing LanguageRuntime: lint → GateReport, build → BuildResult with a workspace-relative error_file, skeleton → the buildable placeholder. Wrappers must be standalone — they never import codeverse.
  3. Add the branch in languages/base.py::get_runtime.
  4. Write prompts/<lang>/contract.md + cookbook.md. Every snippet must actually run — tests/prompts executes them.
  5. Optional but valuable: runtime.file_for_part() so refine tasks can fan out across part files (blender and threejs have it; tracks/prompting.file_for_target_factory picks it up automatically).

A new spatial tool

  1. A pydantic args model plus @tool("name", Args, "description", tracks=(…), languages=(…), cost_hint="fast|slow") in spatial/tools*.py (imported from spatial/tools.py).
  2. Return an Observation. That is it — the tool is now available as a direct call, over MCP, as an api-agent function and as a prompt card.
  3. Update EXPECTED_TOOLS in tests/spatial_tools — and the table in §06 of this page, which the doc test compares against the live registry.

A new backend

  • ChatModel: models/<provider>.py + a branch in models/registry.py + price rows in models/pricing.py.
  • CodingAgent: agents/<kind>.py built on agents/cli_common.py (sessions, retries, files_changed attribution), a branch in agents/registry.py::KINDS, and the MCP wiring in agents/materialize.py.

A new rubric

One YAML file under judges/rubrics/:

pass_threshold: 0.72
criteria: [{id, weight, floor, title, description, anchors, kind}]
caps:     [{id, cap, when: gate|acceptance|console|missing_views, gate, severity, kinds}]
defects:  [{id, text, penalty, cap}]

Weights should sum to 1.0. caps[].kinds matches GateFinding.data["kind"], so a new gate becomes a hard cap without touching judge code. Tracks pick their rubric via TRACK_INFO; 3dcv judge maps track → rubric in cli/main.py.

A new track, or a new battery

  • Track: subclass tracks/lifecycle.py::BaseTrack (hooks: make_pipeline, prepare, baseline_tasks, refine_tasks, round_files_hint), add a RoundPipeline, a plan model in contracts/plan.py, the .j2 prompts, a row in TRACK_INFO and a branch in tracks/base.py::get_track. tracks/graphics.py is the template for a track with its own planner and no GLB.
  • Battery: bench/prompts/<name>.yaml with name, track, language, prompts[{id, tier, category, prompt, must_have, dimensions_m}], then 3dcv bench run … --out bench/out/<name> and 3dcv bench report bench/out/<name>. Runs stream to results.jsonl and re-running the same --out resumes.

Known limits, stated plainly

  • Flash is a lenient, noisy judge on fine distinctions (std ≈ 0.08–0.12 at n = 3); use pro, or n_samples ≥ 3, for anything decisive. Detail crops are still position-heuristic — there are no 2D part boxes yet.
  • Articulated candidate selection uses the quick 4-view sheet rather than pose views; mimic joints are ignored; the sweep is O(links² × poses).
  • Scenes: fps is a relative cost only, and the camera-in-geometry check can miss open-backed enclosures.
  • three.js textures are stripped on GLB export (the texture pass re-adds them as a derived pack), and userData.tick cannot survive export.
  • Repair-pair mining only understands api-agent transcripts; CLI backends produce raw stdout. agy exposes no per-workspace MCP, no cost and no served model.
  • Anthropic and OpenAI are mock-tested only on this box. ffmpeg is absent, so turntables fall back to GIF.
