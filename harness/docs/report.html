3dcodeverse harness

A measurement instrument for LLM-authored raw 3D code — bpy, CadQuery, three.js, URDF, GLSL — across four tracks and eight backends, with deterministic gates ahead of every VLM judgement.

01 Verdict

What the measurements actually support

Read this first

Every number below is a paired comparison: the same prompt, the same fixed judge (gemini-3.1-pro-preview, n_samples 2), the two arms run in the same weather. Cells lost to a provider outage are infra_failed and excluded from every rate — never scored 0. Unpaired means over different prompt sets are not comparable and are not used for any claim here.

02 What it is

A flywheel, not a generator

The harness takes a one-line prompt and a chosen track, drives a model to write raw source in the target language, then builds, measures, renders and judges the artifact — repeating for a bounded number of rounds. Every round is a git commit of src/, every model call is a priced Usage row, and every run ends as a record.json that the flywheel turns into dataset samples, preference pairs and captions.

Tracks and languages

TrackLanguagesDeterministic gates before the judge
static_objectblender · cadquery · threejslint → build → measure → connectivity → contract → 8-view render
articulated_objecturdf_blender+ joint sweep, per-pose collision, link-hierarchy part count

graphicsglsl_shader · opengl_python+ shader compile, GL frame capture, frame statistics

Backends it drives

Five agent kinds — api-agent (in-process, tool-calling), gemini-cli, claude-code, codex, agy — plus single-shot:<provider>:<model> for one-call generation. Providers: Gemini, Anthropic, OpenAI. The same Spec runs on any of them, which is what makes the comparisons in §6 possible at all.

The law that shapes everything

Generated code is raw language, never an SDK. The model writes the same bpy a human would; the harness owns the wrappers, exporters and render rigs. That is the difference between measuring a model's 3D reasoning and measuring how well it can call a helper library.

03 Architecture

One run, end to end

Spec
prompt + track + language + dims + must-haves, validated as a typed contract
Brief
optional: one cheap call expands the prompt into real dimensions and sub-assemblies
Plan
typed part list with bboxes, materials, attachment; budget derived from the request
Generate
agent writes raw source; per-part scoping for large objects
Gates
lint → build → measure → connectivity → contract — all deterministic, all in code
Render
8 canonical views + montage, GPU headless Chrome or Blender
Judge
VLM scores a rubric; the score is computed in code from weights, caps and floors
Refine
repair / refine / detail rounds until pass, plateau or budget
Record
record.json → dataset samples, preference pairs, captions, gallery

The six laws

  • Raw language only — no SDK or helper import in generated code.
  • One source of truth for frames — conventions.py alone states units, axes and naming; every package imports, none restates.
  • Deterministic first, VLM last — code decides geometry; the model is used only for perception. Scores are computed from rubric weights, with explicit caps and floors.
  • Cheap first — lint before build before gates before renders before the judge. Budgets are hard ceilings.
  • Everything is a record — every round a git commit, every call a priced Usage, every run a record.json.
  • Export as authored — no wrapper silently re-centres or grounds an object; the gates catch it instead.

04 Implementation

The parts that carry the weight

Deterministic gates — where the harness earns its lift

The judge never decides whether geometry is correct. spatial/ measures it: part count over the real link hierarchy, pairwise interpenetration depth and buried-surface fraction, floating-component detection against declared attachment, joint sweeps over poses with per-pose collision, camera framing and inter-frame motion for scenes, GL frame statistics for shaders. A finding carries a severity, a target, a fix hint and structured data, and the round loop feeds those back as the repair prompt.

Key pool — 22 keys, scheduled on tokens not requests

Measured on this machine: a generator call averages ~42k prompt tokens, so 1M TPM per key is ~24 calls/min — the token quota binds long before the request quota. KeyPool reserves estimated prompt tokens on acquire and reconciles on report. The measured concurrency knee is 64 in-flight (72.9 calls/min, against 43.9 at 32 and a fall back to 47.2 at 128). Because the pool is per-process, the operational rule is that the sum of in-flight caps across every harness process stays at the knee.

Retry policy — bounded in time, not in attempts

No single wait exceeds 5 s; with 22 keys, rotating beats sitting out a backoff. A capacity storm gets its own patience budget, and the whole retry sequence for one logical call is bounded by a 900 s deadline — before that bound existed, 60 storm attempts × a 300 s read timeout meant one call could hold for 5.6 hours.

Cost ledger

Every model call is priced into telemetry/cost.jsonl with its price provenance, attributed to a stage and a role, nested per run so a parallel battery still attributes correctly. Three profiles — economy, balanced, quality — move models, judge samples, rounds, candidates and ceilings together on one dial.

Honest failure accounting

A cell can end without a score for reasons that say nothing about the model. infra_failed (provider outage) is excluded from score, build rate and wall-clock. budget_exhausted (ran out of time with no artifact) has no score but still counts against build rate. A model that answers with prose, unparseable code or a genuine API mistake keeps its zero. Getting this wrong is not cosmetic: it once put five hard zeros on a one-shot arm while dropping the harness cells hit by the same outage.

05 The noise floor

What a single comparison can and cannot tell you

A/A calibration — the most important result here

Two A/A runs — identical arms, same prompt, same judge, differing only in run-to-run randomness — measured +0.344 and −0.100. A rig with a ±0.02 keep/revert threshold would have concluded keep from one and revert from the other, from nothing at all.

So a single prompt pair carries no signal. Every claim in §6 is therefore reported with its paired standard error, a 95% confidence interval and an exact sign test, and anything whose interval crosses zero is labelled unsupported however good the mean looks.

The practical consequence: an 8-prompt battery resolves a real difference of roughly 0.25, not 0.02. Differences smaller than that need either many more prompts or a within-prompt design.

The finding worth keeping

The harness lift is largest on the weakest model and shrinks as the model gets stronger: luna +0.291 (solid, 10W/0L), terra +0.191, sol +0.155. The loop compresses the gap between models rather than scaling with them — which is exactly what a good scaffold should do, and it is why a cheap model inside the harness reaches a strong model's one-shot quality.

What is not yet true

Paired on the 8 shared prompts, harness+flash − one-shot gpt-5.6-sol = −0.002 (CI −0.118…+0.114). That is a dead heat, not a win. The goal of beating sol with flash alone is currently at parity. The remaining gap to close is the +0.169 that harness+codex-sol still holds over harness+flash (8W/0L, solid) — on blender objects. On graphics and scene the same comparison, harness against harness on 6 paired prompts (§11), is +0.014 with a CI that crosses zero: there the generator makes no measurable difference at all.

10 Known open

Stated, not buried

  • CodingAgent.available() is a false green light. It returns available for agy:gemini-3.7-flash (cannot launch) and codex:gpt-5.1-codex (backend rejects with HTTP 400). Usability, not correctness — it cannot corrupt an artifact.
  • Two pre-existing flaky tests in test_cost_latency and test_prompts_assets. They predate this pass and were deliberately left alone so their attribution stays clean.
  • The scene track has no scored after-measurement. Four deterministic gate defects were found and fixed — a judge shown the harness's diagnostic rig instead of the scene's authored cameras, two false-positive gates, and unverifiable planner must-haves — and two are proven offline on recorded frames. Their effect on scores is not yet measured.
  • The interpenetration study needs recomputing. Its correlations were measured with the connectivity gate that was blind to non-watertight parts.
  • max_minutes is enforced at billing points, not on a timer. The retry deadline makes every call terminate, so the ceiling is evaluated again — but a run whose calls never complete is still not checked against it.
  • The skills library ships OFF, and no bundle has a measured effect. 13 bundles, each with a falsifiable target metric and a corpus baseline (docs/SKILLS_LEDGER.md); the A/A floor on those metrics needs ~90–1,300 pairs to resolve a 25% move, and one bundle was cut for failing its own claim. Honest default until a measurement exists.
  • A budget stop with zero judged rounds is an outage, not a score. On the 2026-08-26 storm, cells burned their 60 minutes without one judged round and were recorded budget; the pairing treats them as unscored but the status should say infra_failed.
  • Fifteen files exceed the ~400-line law (the review names them). Not split in the cleanup — 0 lines saved, every one pinned by tests; one split per wave, starting with orchestrator/rounds.py.

What it establishes

Mean +0.014, sd 0.065, 95% CI [−0.038, +0.066], sign 4/6, p = 0.69; the largest single delta (0.092) is inside the 0.202 generator-alone floor. Picture winners split 3–3 by reviewers blind to the scores. Not a win for either — and not what "flash beats sol" would need; what it does support is that on these tracks the harness loop, not the model, sets the score. The two models fail differently: codex is the tidier renderer and the more literal clause-follower whose failure is a clean image of something adjacent to the brief; flash puts the named subject on screen more often and fails on craft. The rubric currently rewards artefact-absence over subject-presence — a rubric decision, not a model result.

The code is the dataset — so it gets its own vector

flywheel/code_quality.py: unnamed numeric literals per 100 LOC, longest and mean function length, functions defined and never referenced, duplicated 6-line windows, docstring coverage, named constants — folded to one stated-weight index in record.extra["code_quality"] beside the artifact's complexity block. Over 258 measurable runs it computes in 5.8 s; blender's median index is 0.444; correlation with the judged score is +0.10 — a different axis from the picture, which is the point. A tidy stool scores 0.892; the same stool as a script of literals scores 0.400.

The wave, at 07:10 — and the cap it exposed

16 hard, design-realistic object prompts (blender 10, cadquery 3, threejs 3), skills-OFF vs skills-ON, plan-pinned, on all 22 keys, through a night of Gemini 503 storms (outage rows are redone from a fresh driver, never scored). Six real pairs so far, ON − OFF: harp +0.012, microscope +0.087, gate_valve −0.058, ships_wheel −0.256, jukebox −0.326, street lamp −0.362 — mean −0.150, sd 0.188, sign 2/6, against a paired noise floor of 0.202. Nothing here says the library helps; skills stay OFF.

Three ON cells landed on exactly 0.600, which is what a cap looks like from the outside. The street lamp's was false: the connectivity gate had measured "all 9 parts connected, gap ≤ 2 mm" and said so in the judge's input; both pro samples read the dark seam under the pedestal as "floating in mid-air, a clear daylight gap", ticked floating_part, and the checklist cap held the run at 0.600 (uncapped 0.720) against 0.962 for a sibling the eye cannot tell apart. Fixed in code, not in the prompt: a checklist defect whose subject a passed gate measured absent no longer penalises or caps (judges/caps.measured_absent, named in the verdict tail). Re-aggregating all eleven judged cells from their stored samples moved exactly that one score (0.600 → 0.720; pair −0.242); the other 0.600s are must-item and interpenetration caps the gates agree with. With it, the wave reads mean −0.130, sd 0.167 — the same answer.

The graphics judge, measured against an eye — and the loop that fixes it

Seventeen judged graphics runs were scored by a person from the same contact sheets. Against the loop-time shader_v1 verdicts: Spearman 0.16, judge mean 0.773 vs eye 0.550 — three aurora versions nobody would take for an aurora at 0.78–0.94 with empty issue lists, hard pastel discs for bokeh at 0.92, a lifted purple wash for a nebula at 0.82, a crisp ukiyo-e wave at 0.59 under planner must items. The rubric scored the nouns of the brief being present. shader_v2 scores likeness (would someone who has seen the thing accept it), tonal range, and a checklist of what flash actually draws (comb artefact, opaque shapes for light, white wash, candy saturation, no dark range). Re-judged in the same replay (pro n=2, plan digest + frame metrics): v1 0.34 → v2 0.71, mean 0.562 against the eye's 0.550. Reference photos now ride with the brief (bench/refs/<id>/): the agent sees them on its first message and a LikenessJudge puts them beside the frames — the first aurora run with photos was judged 0.49 (“rigid evenly spaced bars, not folding curtains”) where the same picture scored 0.94 the day before, and its refine round reached 0.70 with folded curtains. docs/GRAPHICS_LOOP.md is the recipe and the ledger.

The scene track measures placement now

Audited: no deterministic placement check existed on scenes — floating/sunken assets were a −0.06 VLM opinion, the rubric's floating cap could never fire, and scene agents called the object tools 0 times in 52 sessions (they fail on a scene workspace). spatial/scene_placement.py + runtime_js/lib/host_placement.mjs: per placed asset, a vertical column index of every other mesh gives the gap under its feet, burial depth judged against its own height, water, contacts and 3-D interpenetration; a scene_placement gate whose ERRORs cap the round and route to the zone file, and a check_placement tool the prompts tell the agent to call after every build. 131 k-tri terrain + 450 assets in 71 ms.
