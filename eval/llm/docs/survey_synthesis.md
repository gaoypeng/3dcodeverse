# Evaluating LLMs/VLMs on 3D-code generation: a survey synthesis (as of 2026-09-08)

Scope: public benchmarks, datasets and metrics where the model output is a *program* that produces 3D content (bpy, CadQuery/OpenSCAD/FreeCAD/FeatureScript, Infinigen/procedural, GLSL, three.js, scene-layout and animation code), plus general code / VLM-judge / 3D-metric methodology that transfers. Per-benchmark records (≈130 entries, every number copied from a primary source) are in `00_records_all.md` next to this file; this document is the synthesis. Numbers below are quoted as reported; "n/f" = not found in an accessible primary source.

## 2. Metric taxonomy, pitfalls, and what tracks humans

**(a) Validity / execution rate.** Definitions differ by an order of magnitude in strictness: "no exception" (Text-to-CadQuery, BlenderLLM E_syntax), "≥1 mesh object" ([3DCodeBench](https://arxiv.org/html/2606.01057)), "non-empty export" ([RealCADBench](https://arxiv.org/html/2609.03773)), "volume > 1e-6 mm³" ([BenchCAD](https://arxiv.org/html/2605.10865v1)), "compiles ∧ watertight" ([CADEvolve](https://arxiv.org/html/2602.16317v1)), "valid solid, no non-manifold" ([CADBench](https://arxiv.org/html/2605.10873v1)), "executes ∧ B-Rep ∧ STEP round-trip" ([CADEngBench](https://arxiv.org/abs/2608.09296)). Pitfalls reported: (i) *empty output passes* unless a mesh/volume gate exists — 3DCodeBench's formula explicitly requires `|Mesh| ≥ 1`; (ii) *compile–correctness divergence*: Mage found compile-pass anti-correlated with mechanism F1 (≈0.12 at 43% runtime pass, [arXiv 2605.07342](https://arxiv.org/abs/2605.07342)); Text2CAD-Bench found domain models with IR 2–11% but CD 219–267 and IoU≈0 ([arXiv 2605.18430](https://arxiv.org/html/2605.18430v1)); WorldCoder-Bench found screenshot/DOM scores uncorrelated with hidden-state correctness (τb = −0.02, [arXiv 2606.01869](https://arxiv.org/abs/2606.01869)); (iii) *survivor bias*: computing CD/IoU only on executed outputs rewards models that fail often — RealCADBench's Kimi K3 has 34% exec but the highest IoU among survivors; Text2CAD-Bench flags it; [IterCAD-Bench](https://arxiv.org/abs/2606.13368) introduces AUC-TR that counts non-executing samples; 3DCodeBench reports both "conditional" and "penalized (failure = 0)" aggregates. (iv) *API drift as a confound*: Blender 4.x→5.0 deprecations were the dominant failure in 3DCodeBench (two models excluded at <10% exec); ManiBench names "syntactic hallucination" of non-existent APIs ([arXiv 2603.13251](https://arxiv.org/html/2603.13251)). P3D-Bench's error taxonomy (syntax / undefined reference / parameter / geometry) and its finding that OpenSCAD is the most stable format while CadQuery has the highest syntax-failure rate are directly reusable.

**(b) pass@k.** Use the unbiased estimator pass@k = E[1 − C(n−c,k)/C(n,k)] with n > k samples ([Chen et al. 2021](https://arxiv.org/abs/2107.03374)); LiveCodeBench uses n=10 at T=0.2/top-p 0.95 ([arXiv 2403.07974](https://arxiv.org/html/2403.07974)). In 3D code, pass requires a geometric oracle: 3D-PreMise's GPT-4 Pass@1 17.5% vs Pass@5 19.3% ([arXiv 2401.06437](https://arxiv.org/html/2401.06437v1)) shows how flat pass@k is when failures are systematic. Beware *oracle best-of-N*: CAD-Recode and cadrille select the min-CD candidate of 10 *against ground truth*, so their CD/IoU are not pass@1 numbers ([arXiv 2412.14042](https://arxiv.org/html/2412.14042)). Beware mislabelled metrics: Text-to-CadQuery's "top-1 exact match 69.3%" is a Gemini render-judge "same object?" rate, not string match ([arXiv 2505.06507](https://arxiv.org/html/2505.06507)).

**(c) Chamfer / EMD / F-score / IoU.** Conventions are mutually incompatible: 1k points + ICP (CADPrompt), 2k (DeepCAD/GenCAD), 8,192 (CAD-Recode), 10k squared (Text-to-CadQuery, CADSmith), 30k unit-bbox (Text2CAD-Bench), 100k (CADFS, OccNet, MeshCoder); squared-L2 (Achlioptas/PointFlow) vs L1-mean in bbox/10 units (OccNet, [arXiv 1812.03828](https://ar5iv.labs.arxiv.org/html/1812.03828)); median vs mean (Text2CAD: median 0.37 vs mean 26.41 ×10³; CADEvolve and CADmium choose median "to reduce invalidity/outlier bias"). Alignment: [UNICORN](https://ar5iv.labs.arxiv.org/html/2204.10310) calls unit-cube normalisation + scale-aware gradient ICP "crucial for an unbiased evaluation"; CADBench uses Procrustes, RealCADBench/CAD-Coder signed-PCA over rotation combos, P3D-Bench a 4-step normalise/translate/rotate/bounded-scale search; Blender is Z-up while three.js is Y-up, so unaligned CD is meaningless across dialects. Known failure modes: CD is outlier-dominated ([Tatarchenko et al. 2019](https://ar5iv.labs.arxiv.org/html/1905.03678), who recommend F-score at τ ≤ 1% of bbox side) and density-blind ([DCD, NeurIPS'21](https://arxiv.org/abs/2111.12702)); CD-based RL rewards get hacked on thin parts via sparse sampling ([CAD-Coder-CoT](https://arxiv.org/html/2505.19713)); wrong-topology objects can beat correct ones on CD/IoU ([EvoCAD](https://arxiv.org/html/2510.11631v1)); a house can score well on Chamfer and fail every structural test ([DreamHouse](https://arxiv.org/html/2603.24866v1)); CD/IoU "fail to account for the space of valid design variations" a prompt allows — property tests agree with humans at F1 0.938 vs CD AUC 0.663 ([CADTestBench](https://arxiv.org/html/2605.07807v1)). IoU needs watertight solids (resolution 32³ MeshCoder → 96³ RealCADBench → 256³ BenchCAD/Text2CAD-Bench; exact CSG in P3D-Bench); three.js triangle soups are non-manifold and were excluded from topology/part scoring in P3D-Bench. Topology-aware additions now common: Euler characteristic (CADmium, EvoCAD), open/inverted/non-manifold edge ratios (P3D), Betti numbers (CADGenBench), OCCT checks (MUSE), SegE/DangEL/SIR/FluxEE (CAD-MLLM).

**(d) Render-based image metrics.** Pixel loss/SSIM/LPIPS are valid only with identical camera, lighting and framing (BlenderGym's edit setting); SSIM is "highly sensitive to translation, scaling, and rotation" and LPIPS beats it only modestly on 2AFC (69–70% vs 63.1%, [Zhang et al. 2018](https://ar5iv.labs.arxiv.org/html/1801.03924)). CLIPScore saturates and is compositionally blind: Kendall τ 0.06 on shape in [T2I-CompBench](https://arxiv.org/html/2307.06350v3), pairwise accuracy 50.8% ≈ chance on GenAI-Bench ([arXiv 2406.13743](https://arxiv.org/html/2406.13743)), gameable by text copied into the image (ROT13 test in [TikZero](https://arxiv.org/html/2503.11509)), and CodeGen-3D reports judge preferences diverging from CLIP. What does track humans on 3D renders: view-paired SigLIP-2 (Pearson 0.964) and DINOv3 (Spearman 0.972) against 3DCodeBench's Elo; multi-view 3DGen-Score alignment 0.725 vs CLIP 0.661 ([3DGen-Bench](https://arxiv.org/html/2503.21745v1)); DINO is the better identity/shape proxy than CLIP-I ([DreamBooth](https://ar5iv.labs.arxiv.org/html/2208.12242)). Preference scorers (HPSv2, PickScore, ImageReward) are trained on photoreal T2I and correlate only 0.51–0.62 SRCC on textured meshes ([MATE-3D](https://arxiv.org/html/2412.11170v1)); FID anti-correlates with users (−0.90, [PickScore](https://arxiv.org/html/2305.01569)).

**(e) VLM/LLM judges.** Position bias is severe: GPT-4 only 65% consistent under answer swap ([MT-Bench](https://arxiv.org/html/2306.05685)); GPT-4V's text-to-image position consistency 51.5% ([Zhang et al. 2023](https://arxiv.org/html/2311.01361)); BlenderGym's Qwen verifier "consistently favor the second edit candidate". Absolute scoring correlates poorly (GPT-4V Pearson 0.49; pairwise 0.636, [MLLM-as-a-Judge](https://arxiv.org/html/2402.04788)); MLLMs "are less able to convert into exact grades" (T2I-CompBench). What works: binary checklists derived from the prompt — BlenderLLM's 12–15 checkpoints reach κ 0.791 vs human, ArtifactsBench's 10-item checklist 90.95% pairwise agreement (only 71.34% with a Qwen2.5-VL-72B judge); multi-view grids + normal maps + both orderings + Elo (GPTEval3D, avg Kendall τ 0.71, [arXiv 2401.04092](https://arxiv.org/html/2401.04092)); rubric VLM on already-validated geometry (MUSE r=0.713). Limits: geometry judgments are weak (Eval3D's consistency metrics 83% vs GPT-4V 46.9% on geometry, [arXiv 2504.18509](https://arxiv.org/html/2504.18509)); VLMs miss small local edits ([VIEScore](https://arxiv.org/html/2312.14867)); VLM judges score 0.549 F1 vs 0.938 for property tests (CADTestBench); presentation shifts human votes (+144 Elo textured vs untextured, [3D Arena](https://arxiv.org/abs/2506.18787)); CADFusion warns of same-family bias with a GPT-4o judge, Text2CAD-Bench found none with GLM-4.6V. [3D-DefectBench](https://arxiv.org/html/2607.10826) shows the judge model explains most variance, RGB beats added depth/normal channels, and a 6-view oblique turntable matches 14 views. Report Cohen's κ / Scott's π rather than raw agreement ([Judging the Judges](https://arxiv.org/html/2406.12624)).

**(f) Attribute / constraint / edit metrics.** Deterministic checks are the most human-aligned family: BlendNet checkpoints; SceneEval count/attribute/relation tests (all methods < 30% attribute satisfaction); SimWorlds MPR/SPR predicates with anti-cheat for faked keyframes; WorldCoder hidden state contracts calibrated by mutation testing; BenchCAD essential-op recall (loft/sweep/helix near-zero for pretrained models) and edit accuracy normalised by headroom, revealing ~64% of "successful" edits silently corrupt unrelated features. Sequence-level F1/edit distance (Text2CAD Hungarian F1, DeepCAD command/param accuracy) only applies when the target language is a fixed DSL.

**(g) Decoding degeneration and noise.** Greedy decoding produces repetition loops that hit the token cap (89.9% of repetitive outputs, [arXiv 2504.12608](https://arxiv.org/html/2504.12608v1)); ShaderMatch's `incomplete_generation` bucket reaches 37% for small models; MBPP found greedy best for 1 sample but sampling better for 10 ([arXiv 2108.07732](https://ar5iv.labs.arxiv.org/html/2108.07732)). Pass@1 SD is 5–15 points across seeds on small sets, temperature swings up to 15% ([Sober Look](https://arxiv.org/html/2504.07086)); "deterministic" API settings vary up to 15% ([arXiv 2408.04667](https://arxiv.org/abs/2408.04667)); detecting a 3-point gap needs ≈969 independent items at 80% power ([Miller 2024](https://arxiv.org/html/2411.00640)).

## 3. Dataset-construction best practices distilled

1. **Prompt authoring.** Human-authored, multi-annotator prompts (Text2CAD-Bench: 3 engineers check executability, description–geometry correspondence, tier, cross-style consistency; CADPrompt: 2 writers + selector + verifier; BenchCAD experts with ISO tables; MUSE expert seeds → LLM expansion → human review) versus caption-derived prompts (Text2CAD: LLaVA-NeXT multi-view captions + Mixtral, later re-annotated with Qwen2-VL/Qwen2.5-72B; [Cap3D](https://arxiv.org/abs/2306.07279); 3DCodeBench captions validated by Gemini 3.1 Pro and humans). Provide two styles (geometric vs procedural) — Text2CAD-Bench shows geometric prompts win at L1–L2 and procedural at L3, and frontier IR on text→CadQuery spans 11%–93% across papers purely from prompt format. Prompts derived from the GT representation leak (P3D-Bench: QA-P > QA-S because specs were written from JSON).
2. **Tiered difficulty from a model-independent criterion**: operation count/type (Text2CAD-Bench L1–L4, CADSmith 1–3/3–8/5–15 ops), parameter complexity (BenchCAD easy/medium/hard, >45-point cliff), furniture count (SceneEval), external ratings (LiveCodeBench). Retrospective solve-rate tiers (ArtifactsBench 30/40/30, BigCodeBench-Hard) are acceptable if documented.
3. **Must-have checklists per item**, authored with the prompt: 12–15 binary checkpoints (BlendNet), ~15 property tests with mutation score > 90% (CADTestBench), 10-dimension checklist calibrated to κ ≥ 0.8 among annotators (ArtifactsBench), keep-in/keep-out volumes (CADGenBench). Budget a SWE-bench-Verified-style pass (3 annotators, 0–3 severity for underspecified prompt / over-specific checker; 68.3% of SWE-bench was discarded, [source](https://www.swebench.com/verified.html)) and expect ~10% of reference solutions to be defective ([EvalPlus](https://arxiv.org/html/2305.01210)).
4. **Reference renders**: fixed camera/lighting, 4 canonical azimuths at 45/135/225/315° (3DCodeBench), 6 ortho + 2 iso (CADEvolve), 10 views (Text2CAD); a 6-view oblique RGB turntable suffices for defect detection (3D-DefectBench); ship textured and untextured GLBs because presentation shifts votes (3D Arena).
5. **Seed / perturbation variants**: 60 seeds per category (3DCodeBench), 3 parameter-perturbed twins per core task (WorldCoder-Robust), SE(2)-perturbed programs (SGP-Bench), 15 CMA-ES parameter draws per generator (CADEvolve). These double as contamination probes (GSM1k-style twins).
6. **Dedup and balance**: DINOv2 near-duplicate removal (P3D), MinHash + semantic + screenshot perceptual hash (ArtifactsBench), ROUGE-L on prompts (T3Bench), class dedup (3DCodeBench); cap trivial classes (Text2CAD v1.1 and CADmium reduce cuboids from ~25% to 5%).
7. **Contamination and held-out families**: the DeepCAD 8,046-model test split is shared by Text2CAD, CADmium, UniCAD and IterCAD and sits in the training data of most fine-tuned CAD models; use held-out families (BenchCAD: 10 OOD families; Fusion360 is outside ABC; MCB), private GT with leaderboard-only scoring (CADGenBench), gated generations (Shadereval-runs), date-stamped items with post-cutoff reporting (LiveCodeBench), blind-input baselines as floors (BenchCAD), and a text-only/no-image ablation of the judge prompt ([MMMU-Pro](https://arxiv.org/html/2409.02813)). Always include a retrieval baseline (nearest training asset) — Tatarchenko showed retrieval matches SOTA reconstruction.
8. **Licensing**: Fusion 360 Gallery is non-commercial and non-redistributable; CAD-Recode, Text2CAD, CAD-Editor, CADFusion, ArtifactsBench are CC BY-NC(-SA); Shadertoy shaders default to CC BY-NC-SA 3.0 (tag SPDX per item); Onshape-derived data follows Onshape ToS; Infinigen is BSD-3.

## 4. Recommended protocol for a new multi-dialect benchmark (bpy, CadQuery, OpenSCAD, GLSL, three.js; text→code and image→code; 8B open reference)

**Tasks and items.** Three tracks: text→code, image→code (4 fixed views, 45/135/225/315°), and edit (start program + goal, graded FAIL_TO_PASS/PASS_TO_PASS style: new checks must pass, existing checks must still pass). Per dialect ≥ 200 items (≥ 1,000 total if 3-point model differences must be resolved); tiers by operation count; each item ships prompt (two styles), reference program, reference GLB, 4–6 reference renders, 10–15 binary must-have checks, and ≥ 3 seed/parameter twins. Pin toolchains: Blender 5.x headless Cycles, 240 s; CadQuery 2.6 + trimesh, 60 s; OpenSCAD CLI (nightly/Manifold backend) → STL; GLSL via wgpu-shadertoy at 512×288 at ≥ 10 non-periodic timestamps; three.js in Playwright headless Chromium with a `window.__3D_STATE__`-style export plus GLTF export for mesh metrics. Record the toolchain version in every result row (API-version drift is the largest single confound).

**Metrics to report (all four layers, never one).**
1. *Validity*: exec = runs within budget ∧ ≥ 1 mesh ∧ volume > ε; plus separate flags for watertight, timeout, and token-cap-hit (repetition), and an error taxonomy (syntax / undefined API / parameter / geometry). For GLSL add ShaderMatch's `single_color` and `incomplete` labels.
2. *Geometry*: normalise to unit cube, scale-aware ICP (or search 24 canonical rotations), 100k surface samples; headline **F-score@1% bbox**, plus CD-L1 (bbox/10 units, median and mean), voxel IoU at 128³ only for watertight outputs, normal consistency; Euler/open-edge/non-manifold ratios for CAD dialects; skip topology for three.js. Report *penalized* (failure = worst) as primary and *conditional* as secondary.
3. *Render*: view-paired DINOv3 and SigLIP-2 cosine (the two metrics with r ≥ 0.96 to human Elo in 3DCodeBench); LPIPS only in the edit track (same camera); no CLIPScore headline.
4. *Semantics*: must-have checklist pass rate judged by a frontier VLM given the reference render, both orderings, binary questions only; report κ against a 200-item human-labelled subset and rank correlation with a pairwise human arena (BT-Elo, ≥ 1,000 bootstrap resamples). Composite = geometric mean of layer scores (VIEScore's min-based aggregation is the alternative), never a single scalar.

**Decoding and sampling.** Reference 8B baseline (e.g. Qwen2.5-Coder-7B/Qwen3-8B; comparable public points: Qwen2.5-Coder-7B 0.353 avg / 31.4% syntax errors on CADBench-Sim before self-improvement, Llama-3.1-8B 46.5 on SGP-Bench SVG, deepseek-coder-6.7b ShaderMatch error rate 0.308): n = 10 samples at T = 0.2 / top-p 0.95, seeds fixed, batch size 1; report unbiased pass@1 and pass@5 on the validity+checklist oracle and mean metric over samples; also run greedy as a diagnostic with the token-cap/repetition rate reported (expect degeneration on boilerplate-heavy OpenSCAD/GLSL). API models: provider defaults, n = 5, thinking budget stated. Multi-turn (≤ 2 retries with truncated traceback) and agent-harness settings are separate rows — 3DCodeBench shows retries lift exec 0.70 → 0.97 without changing conditional quality, so single-shot and multi-turn must never be mixed.

**Noise reporting.** Mean ± CLT standard error per metric, clustered by object family; question-level paired differences with CIs for model-vs-model claims; ≥ 3 full seeds (≥ 30 bootstrap draws for pass@k); per-tier and per-dialect breakdowns; state exact temperature/top-p/max-tokens; flag any model excluded for < 10% exec rather than dropping it silently.

**Contamination controls.** Held-out object families never released with code; seed-twin evaluation (score gap between canonical and twin items flags memorisation); release-date stamping; a blind baseline (no prompt / black image) as floor; a retrieval baseline as a ceiling check; text-only judge ablation.
